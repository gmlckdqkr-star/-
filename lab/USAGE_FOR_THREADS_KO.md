# lab 사용 규칙 (연구 스레드용, 2026-11-03)

목적: 백테스트 코드를 매번 새로 쓰지 말고 짧은 명세로 돌려 토큰을 줄인다. 계산과 검증은 로컬에서 하고, LLM은 아이디어와 판단만 맡는다.

## 언제 쓰나
- 가격 패널(research/data/panel_f32.npz.xz)로 표현되는 전략이면 **먼저 lab**을 쓴다. 추세, 변동성, 회전(top-k), 역변동성/위험균형, 상태 래치, 손실 브레이크, 격자 탐색, 거시 경보(macro(k)), 국내 ETF 계좌(account: kr_etf)가 여기에 해당한다.
- DSL로 안 되는 모양은 plugin(파이썬 함수 1개, 격리 실행)으로 쓴다.
- 대상: 미국 상장 ETF 22종(그중 QQQ·QLD·TQQQ·SSO·UPRO·TMF·SPY·TLT·IEF는 기준 판정까지), 국내 지수 ETF 4종(KR200·KRLEV·KRINV·KRSEMI, account: kr_etf, 개발 요약만), **미국 개별 종목**(universe: sp500 — S&P 500 시점별 편입 종목, 상폐·편출 종목 포함, 1970~2014, 개발 구간만, 기준은 `판정 불가 (개별주)`, 예시 specs/examples/stk_*.yaml). 국내 개별 종목은 아직 없다.
- 패널에 없는 비가격 자료(EDGAR, 재무, 뉴스 등)는 아직 lab에 없다(개별 종목도 가격·거래대금뿐). 이런 경우에만 직접 코드를 쓰고, 이유를 보고에 한 줄로 적는다.

## 실행 (복사해서 쓰기)
```
cd /mnt/project-files/research/lab
python3 -B -m lab run <명세.yaml 또는 폴더> --bar quick     # 빠른 선별(기준 아님) + MS1·G1, 명세당 5~25초 (개별주 연속 노출 ~80초)
python3 -B -m lab run <명세> --bar full --workers 4          # 기준 판정(약 2분, 첫 REJECT에서 멈춤)
python3 -B -m lab ledger                                     # 계열별 시험 수 N
```
- MS1·G1은 **자동으로 붙는다**(`--std auto`가 기본). 처음 한 번만 MS1 계산 환경을 설치한다(약 1~2분, 안내 한 줄).
- **읽는 것은 한 줄 결과와 요약표만** 읽는다. 상세 JSON(var/out/)은 필요할 때만 연다.
- 문법은 README.md의 "DSL 요약표"와 "미국 개별 종목" 절을 보고, 예시는 specs/와 specs/examples/를 본다.
- 명세에는 family(계열)와 known(0~3, 알려진 정도)을 반드시 쓴다(없으면 줄에 `(family·known 없음)`, 계열은 unset에 섞임). 격자 점 하나하나가 N에 들어간다. 같은 명세(해시)를 다른 family로 다시 돌려도 시험은 처음 센 계열에 남는다(`(중복: 원장 계열 X, 명세 Y)`).
- 개별주에서 노출을 분수로 매일 바꾸면(`exposure: 'min(1, 0.15 / vol(_NDX, 20))'`) 모든 장부가 매일 거래해 명세당 ~80초다. 격자를 돌릴 땐 `exposure_every: rebalance`(결정일에만 노출)를 쓴다.

## 결과 해석
- 판정 이름은 REJECT / Q60 미달 / PENDING(통합 담당 대기) / 판정 불가뿐이다. lab은 APPLY를 내지 않는다.
- **보고에 인용하는 수치**: ETF 명세는 줄의 MS1 대표값(`MS1 경로 x%`, 하한과 함께), 개별주 명세는 `세후 보수 x%`(상폐 −30% 행, 게이트가 늦게 준비되면 `1986~2014(게이트 1986-07~)`처럼 그날부터)와 `MS1(수익 흐름 재표본) 경로 x%`. `종목 0 (filter/게이트 확인)`이면 명세 오류부터 본다. G1은 줄의 판정(닫음 CLOSE / 보류 HOLD / 설계 BUILD / 60%후보, 상시 보유·개별주는 Sharpe vs 1.1)을 쓴다. **개발 요약(`개발(...) 세후`)이나 빠른 선별 숫자만 인용하지 않는다**(기준 아님).
- `MS1: 해당 없음 (이유)`(보유가 QQQ·QLD·TQQQ·CASH 밖, kr_etf 등)이면 이유를 적고, MS1 수치가 꼭 필요하면 research/measure_std로 따로 잰다.
- `개발 인과성 위반`이면 그 명세는 미래를 읽는다: MS1·G1은 계산하지 않고(`MS1: 계산 안 함`), 요약표 맨 뒤에 `인과성위반`으로 나온다. 숫자를 인용하지 않는다.
- lab은 2014-12-31 이후를 계산하지 않는다(코드로 강제). 2015년 이후 수치는 lab에서 나오지 않는다.
- 판정 경로가 재표본하지 않는 입력(_IRX 등 거시, macro(k), *.KS, KRW_X, GLD, SHY)과 대용 없는 상품(SOXL 등)은 기준에서 `REJECT (version impossible)`로 나온다. 개발 요약과 MS1(자격이 되면)은 계산된다.
- account: kr_etf는 개발 요약만 낸다(편도 13bp, 해외지수 ETF는 매도 건별 15.4% 손실 상계 없음, 국내주식형 ETF는 비과세 가정). 기준 칸은 "판정 불가"로 나온다.
