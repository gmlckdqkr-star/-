신호가 켜진 블록은 46개였다(8개 이상 기준은 충족). 그런데 on 블록의 적중률은 60.9%로, 시대별 base(가중 55.0%)보다 오히려 **5.9pp 높았다**.

## 검증
- 자료: FRED DEXJPUS(H.10 뉴욕 정오 환율, 1971-01-04~), 2014-12-31까지 자른 파일만 읽음(sha256 1a3ed7e5..., MANIFEST.json). 휴일 빈칸 441개는 빼고 거래일로 ffill.
- 시점 규칙: d일 값은 d 다음 거래일부터 사용(정오 환율은 d일 정오에 공개되므로 하루 보수적). 엔진의 2일 실행 지연은 그대로.
- 사전 등록에서 고친 모호점(계산 전): 거래일 = MS1 기준 미국 거래일 달력, 백분위 = numpy 선형 보간, 엄격한 '>', 756개 값이 모두 있어야 정의,
  유지 = t-20..t 중 한 번이라도 발사, 1x = v1의 1x 상태. 신호가 정의되는 첫날은 1974-02-01(1971-73 고정환율·스미소니언 기간이 1974-76 창에 들어감, 사양대로 둠).
- 독립 재계산: 원자료를 날짜마다 직접 찾아(ffill·cumsum·numba 없이) numpy.percentile과 21일 유지 반복문으로 초기 블록 310개 날짜 전부 다시 계산 →
  on 불일치 0, 임계값 최대 차 0 (results/s3_check_early.json). 합성 자료 시험에서도 임계값 코드 = 직접 계산(차 0).
- 블록·라벨은 gate._frame 그대로(3x 상품 3r-2rf-2.45%/년 vs 예금 (rf-2pp)×0.846, t+3..t+23). 라벨이 2000년으로 넘어가는 블록은 초기에서 뺌.
- v1 목표는 L.v1_B를 real 문맥과 같은 방식으로 만들어 씀. 일별 비중 SPX 1974-85: 3x 66.3%, 1x 13.0%, 현금 20.7%; NDX 1986-99: 3x 80.8%, 1x 10.5%, 현금 8.7%.
- N = 1(창·분위·유지 기간 변형 없음). sqrt(1+ln N)=1. 부호가 반대라 보정과 무관하게 FAIL. 2015년 이후 값은 읽지 않았다(원본 다운로드 파일은 있지만 코드는 자른 파일만 읽음).
